# はじめに

Claude CodeなどのAIツールは、コード生成、テスト実行、リファクタリングまで任せられる便利な存在になりつつあります。最近では、用途や作業単位に応じて複数のツール・セッションを並列して使う場面も増えてきました。複数のツール・セッションを並行して使っていると、次のような課題があります。
![](/images/20260531_tech_awt/problem.png =800x)

許可待ちのまま数分間放置してしまうと、その時間は空白の時間になります。AIツールに作業を任せているはずなのに、ユーザー側がAIツールを見張り続ける状態になってしまいます。この課題に対して、macOSのcmuxやWindowsのwmuxのように、ペイン分割やMCP統合などを備えた多機能なAIツール向けターミナルも登場しています。

![](/images/util/dummy_white.png =200x)
一方で、今回作成した **Agent Watch Terminal** は、多機能化ではなく、**AIツールの状態検出と通知に特化したWindows向けの軽量ターミナル**です。主な特徴は以下の通りです。
![](/images/20260531_tech_awt/features.png =800x)
- Claude Code、Codex CLI、GitHub Copilot CLI、Bob Shellの稼働状態を自動検出
- 「実行中」「許可待ち」「アイドル」「エラー」をリアルタイムに追跡
- 入力待ちやエラーを検出したら、OSのトースト通知とタスクバー点滅で通知
- 他の作業ウィンドウの裏で常時起動しておける軽量設計

本記事では、Agent Watch Terminalの設計思想、主要機能、使い方を紹介します。



# 1. 設計思想： 監視に特化
AIツール専用ターミナルには、以下の大きく2つの方向性があります。

- **操作と統合**を強化する
ペイン分割、ワークスペース管理、ブラウザ統合、API／MCP連携、マルチエージェント協調など、エージェントを動かしやすくするための機能を揃える
- **監視と通知**を強化する
エージェントの状態（作業中・完了・入力待ち）を検出し、必要な時だけユーザーに知らせる

Agent Watch Terminalは、後者に特化したツールです。
**AIツールを使っていて最も時間を無駄にしやすいのは**、AIツールの操作ではなく、**AIツールが何かを待っていることに気づかず放置してしまう時間**だと考えました。たとえば、許可待ちのプロンプトが出ているのに5分間気づかなければ、その5分は丸ごと待ち時間になります。この待ち時間を減らすには、まず「状態の検出」と「必要なタイミングでの通知」が重要です。

そのため、Agent Watch Terminalでは、MCP統合やブラウザ自動化よりも、状態検出と通知の信頼性を優先しました。ペイン分割も実装していません。**Agent Watch Terminalが解決したいのは**、複数の出力を同時に読み続けることではなく、**どのセッションに今注意を向けるべきか分かるようにすること**です。その目的には、タブ切り替え、ステータス表示、通知の組み合わせが適していると判断しました。
![](/images/20260531_tech_awt/asis_tobe.png =550x)



# 2. 設計方針
Agent Watch Terminalで実現したいことは、「ターミナル上を流れるテキストだけを手がかりに、AIエージェントが今どういう状態にあるのかを判定すること」です。ただし、実際に実装しようとすると、いくつかの難しさがあります。

- エージェントのTUIは、カーソル移動コードを使って画面を上書き描画する
- 出力が「普通のテキスト」として読み取れるとは限らない
- 出力は非同期で届くため、途中経過なのか最終状態なのかを即座には判断できない
- 複数セッションが同時に動く際に、セッションの判定が干渉し合ってはいけない

これらの技術的な課題に対処するため、以下の3つの方針を採用しました。

1. **二段階ゲート検出で、AIツール識別と状態判定を分離する**
2. **デバウンスやANSI処理により、通知の信頼性を高める**
3. **常時起動を前提に、軽量に動作する構成にする**



## 2-1. 方針1：二段階ゲート検出
Agent Watch Terminalでは、AIツールの検出を以下の2つのステージに分けることで、「どのAIツールが動いているか」と「AIツールが今どの状態か」を独立して判定できます。
![](/images/20260531_tech_awt/judge.png =800x)

- **ステージ1：AIツール識別**
ターミナル出力に Claude Code や Codex などのAIツール固有文字列を検出したら、そのセッションを該当AIツールの監視対象として確定し、以後は専用パターンのみでステータスを追跡します。これにより、無関係な待機プロンプトなどへの誤反応を防ぎます。Ctrl+C などでAIツールが終了したら、ユーザーが利用をやめたものとして監視を解除します。

- **ステージ2：状態追跡**
ゲートが開いている間は、出力内容と出力量の両方を見て状態を判定します。
  - **idle（アイドル）**：シェルプロンプトを検出したら即座に判定
  - **running（実行中）**：3秒以上の継続的な出力を検出したら判定
  - **waiting（許可待ち）**：`Do you want to` などを検出し、3秒のデバウンス後に確定
  - **error（エラー）**：エラー固有のパターンを検出し、3秒のデバウンス後に確定

  シェルプロンプトとは、`PS C:\>`や`user@host$`のようなものです。これらを検出した場合は、エージェントの処理が終わってシェルに戻ったと判断します。一方で、許可待ちやエラーは一瞬だけ表示されることがあります。そのため、即座に確定せず、デバウンスを挟んでから判定します。



## 2-2. 方針2：通知を信頼できるものにする

監視ツールにとって最も重要なのは、通知が信頼できることです。
- 鳴るべき時に鳴る
- 鳴らなくてよい時は黙る
- 同じ状態で通知が連発されない
- ユーザーがすでに見ている時は通知しない

以下の状態を実現するため、Agent Watch Terminalでは複数の仕組みを組み合わせています。
![](/images/20260531_tech_awt/policy1.png =800x)
![](/images/20260531_tech_awt/policy2.png =800x)
- **方針2-1. デバウンスで誤検出を防ぐ**
TUIアプリケーションでは画面再描画により、Do you want to のような文字列が一瞬だけ出力されることがあります。これを即座に「許可待ち」と判定すると誤通知につながるため、Agent Watch Terminalでは、出力停止から3秒後に直近数KBのリングバッファを再確認します。その時点でもパターンが残っていれば「許可待ち」や「エラー」として確定し、再描画中に一瞬だけ現れた文字列は無視します。通知は最大数秒遅れますが、誤通知を減らすことを優先しています。

- **方針2-2. ANSIスペース置換で見逃しを防ぐ**
AIエージェントのTUIでは、単語間のスペースがANSIカーソル移動コードで表現されることがあります。見た目は `Do you want to` でも、実際には `Do\x1b[3Cyou\x1b[3Cwant\x1b[3Cto` のようなバイト列になり、ANSIコードを単純に削除すると `Doyouwantto` になってしまいます。そこで Agent Watch Terminal では、ANSIカーソル移動コードを削除せずスペースに置換し、表示上の文字列に近い形でパターンマッチします。小さな処理ですが、検出精度に大きく影響するポイントです。

- **方針2-3. 正規表現を採用**
状態検出には、正規表現ベースのパターンマッチングを採用しています。AIエージェントが発するプロンプトは、比較的決まった形式を持っています。そのため、正規表現でも十分にカバーできます。また、正規表現を使うことで、以下のメリットもあります。
  - 軽量
  - デバッグしやすい
  - 同じ入力に対して同じ結果を返す

- **方針2-4. フォアグラウンド検出で不要な通知を抑える**
Agent Watch Terminalがフォアグラウンドにある時、トースト通知やタスクバー点滅は発火しません。ユーザーが既にターミナルを見ている場合、「許可待ちです」と通知する必要はないと考えており、ユーザーが別のウィンドウで作業している時に通知する仕様としています。


## 2-3. 方針3：常時起動に耐える軽量設計

Agent Watch Terminalは、他の作業ウィンドウの裏で常時起動しておくことを想定しています。いわば、エージェントの状態を見守る「番人」です。その番人自身がCPUやメモリを大きく消費することは避けるべきです。そのため、軽量に動作することも重要な設計方針にしました。
![](/images/20260531_tech_awt/policy3.png =800x)

- **方針3-1. 正規表現を採用**
正規表現を採用した理由は、AIツールの状態判定の信頼性だけではありません。リアルタイムに流れるPTY出力を低負荷で処理できる点も重要です。毎回パターンを組み立てるのではなく、事前にコンパイルしておくことで、CPU負荷を抑えています。監視ツールとして常時起動することを考えると、状態検出の処理はできるだけ軽い必要があります。

- **方針3-2. pywebviewを採用**
Agent Watch Terminalでは、GUIフレームワークにpywebviewを採用しています。Electronは高機能ですが、Chromiumを同梱するため重くなりがちです。一方、pywebviewはOS標準のWebViewを利用するため、WindowsではWebView2により軽量に構成できます。多機能にするならElectronも有力ですが、Agent Watch Terminalの目的は「監視と通知」に絞られるため、軽量なpywebviewの方が適していると判断しました。



# 3. 使い方
## 3-1. pythonインストール
Agent Watch Terminalを使うには、事前にPython 3.12以上をPCにインストールしておく必要があります。
:::details Pythonのインストール方法
[こちらの公式ページ](https://www.python.org/downloads/)で最新の安定板のPythonのバージョンを確認します。（2026年５月現在では、3.12です。）確認したバージョンのインストーラーを[こちらの公式ページ](https://www.python.org/downloads/windows/)から取得し、画面に沿ってインストールを進めます。**最初の画面で「Add Python 3.xx to PATH」にチェックを入れるようにしましょう**。
![](/images/20260531_tech_awt/setup_python.png =400x)
:::


## 3-2. Agent Watch Terminalセットアップ
Pythonインストール後、資材をGitHub★からダウンロードし、ローカルの任意の場所に配置後、以下のコマンドでセットアップできます。

```bash
cd [資材配置場所（資材のappフォルダ配下に移動）]
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

起動は以下のコマンドです。PCの状態や設定によっては15秒程度かかる場合があります。15秒以上経っても正常に起動しない場合は、「[5. トラブルシュート](https://zenn.dev/stockdatalab/articles/20260531_tech_awt#5.-%E3%83%88%E3%83%A9%E3%83%96%E3%83%AB%E3%82%B7%E3%83%A5%E3%83%BC%E3%83%88)」を参考にして再起動してみてください。

```bash
python main.py
```

:::

# 4. 主要機能
ここからは、Agent Watch Terminalの主な機能を紹介します。


## 4-1. マルチセッションターミナル
Agent Watch Terminalは、通常のターミナルとしても使えます。PowerShellが動作し、コマンド実行、コピー＆ペーストなど、基本的なターミナル操作に対応しています。特徴的なのは、複数のターミナルセッションを管理できる点です。複数のAIツールを並行して使う場合でも、各セッションの状態を一覧で確認できます。
![](/images/20260531_tech_awt/feature_sessions.png =800x)


## 4-2. AIツールの自動検出と状態追跡
Agent Watch Terminalの中核機能は、AIエージェントの自動検出と状態追跡です。ユーザーが特別な操作をしなくても、バックグラウンドで検出と追跡が行われます。

ターミナル上でAIツールを起動すると、出力に含まれる特徴的な文字列からAIツールの種類を自動判別します。対応しているエージェントは次の4つです。
- Claude Code
- Codex CLI
- GitHub Copilot CLI
- Bob Shell

エージェントを検出すると、サイドバーのセッション一覧にエージェント名とステータスが表示されます。ステータスは次の4種類です。
| ステータス       | 意味                      | 色   |
| ---------- | ---------------------- | -- |
| **idle**    | エージェントが待機中、またはシェルに戻った状態 | グレー |
| **running** | エージェントがコード生成や処理を実行中     | 緑   |
| **waiting** | ユーザーの許可や入力を待っている状態      | 黄   |
| **error**   | エラーが発生した状態              | 赤   |



## 4-3. デスクトップ通知
エージェントのステータスが「許可待ち」や「エラー」に変わると、Windowsのトースト通知とタスクバー点滅で知らせます。前述の通り、**Agent Watch Terminalを見ている時には通知しない仕様**になっています。
また、現在開いていないセッションで状態変化があった場合は、サイドバーのセッション名に未読バッジが表示されます。これにより、どのセッションに着目すべきか一目で分かります。
![](/images/20260531_tech_awt/feature_notification.png =800x)


## 4-4. ファイルエクスプローラ
Agent Watch Terminalには、サイドバーにファイルエクスプローラを搭載しています。ターミナルのカレントディレクトリが変わると、「更新」ボタン押下時にファイルツリーも更新されます。これにより、エージェントがどのディレクトリで作業しているのかを視覚的に確認できます。（WSL内でディレクトリを移動した場合も、ファイルエクスプローラが追従します。）

Markdownファイルをダブルクリックすると、アプリ内でプレビュー表示できます。AIツールが生成したドキュメントを、その場で確認する用途に便利です。なお、その他のファイルもAgent Watch Terminal上で開けますが、**基本的にはコードを人間が直接修正するのではなく、AIツールで編集する使い方を想定**しています。そのため、VS Codeのような変数の色分けなど、**手作業で編集しやすくするための機能は備えていません**。
![](/images/20260531_tech_awt/feature_file.png =800x)


## 4-5. セッションの保存と自動復元
Agent Watch Terminalを終了しても、セッション情報とターミナルの表示内容は保存されます。次回起動時には、前回のセッション構成が復元されます。ターミナル画面も、終了時の状態に近い形で再現されます。さらに、AIツールのセッション自動復元にも対応しています。

Agent Watch Terminalを閉じる際に、動作中のAIエージェントのセッション名を記録しておき、次回起動時に再開用の`resume`コマンドを送信できるようにしています。これにより、前回の作業状態から再開しやすくなります。



# 5. トラブルシュート★（ログ出力デフォルト設定★））
## 5-1. 15秒以上経っても正常に起動しない場合
Agent Watch Terminalの右上の「×」やタスクマネージャーからAgent Watch Terminalを終了し、再度`python main.py`で起動します。再起動しても正常に起動しない場合は、セッションを管理している以下のファイルを削除して、アプリを再起動してみてください。（ファイルを削除すると、アプリ起動時にresumeコマンドは実行されません。）
```
app/
└── data/
   ├── sessions.json
   └── session_ids.json
```
## 5-2. ファイルエクスプローラの表示が見切れる場合
Agent Watch Terminalの右上の「□」（画面の拡大・縮小）を押下したり、ファイルエクスプローラのエリアを開閉したりしてみてください。
![](/images/20260531_tech_awt/trouble.png =650x)



# おわりに
Agent Watch Terminalは、**AIツールの出力を見張り続ける時間を減らす**ための、状態検出と通知に特化した軽量ツールです。また、**AIツールの自律実行時間が長くなるほど、AIツールの状態を効率よく把握する手段は需要が高まる**と思われます。cmuxやwmuxのようなペイン分割やMCP統合は無い代わりに、常駐して必要な時だけユーザーに知らせることを重視しています。

許可待ちやエラーをOS通知で受け取れるため、エージェントに任せている間も別作業に集中できます。複数セッションは状態ラベルや未読バッジで把握でき、二段階ゲート検出、デバウンス、フォアグラウンド検出により不要な通知も抑えます。
