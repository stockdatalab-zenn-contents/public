#### 学習形態によるアプローチ分類
|      カテゴリ      |                     概要                 |              代表例             |
|     ----           |                     ----                 |              ----               |
|教師あり学習        |正解ラベル付きで予測モデルを学習          |線形回帰、決定木、SVM、深層学習など|
|教師なし学習        |データ構造の発見・パターン認識            |クラスタリング（k-means）、PCA、Autoencoder|
|強化学習            |試行錯誤から報酬最大化を学ぶ              |Q学習、DQN、Policy Gradient|
|半教師あり学習      |ラベル付き＋未ラベルの混合学習            |Semi-supervised GANなど（補足程度）|
|自己教師あり学習    |ラベルを自動生成して学習                  |SimCLR、BYOLなど（補足程度）|


#### モデル構造・アルゴリズムによる分類
|      カテゴリ      |                     概要                 |              代表例             |
|     ----           |                     ----                 |              ----               |
|線形モデル系|入力と出力を線形関係で表現|線形回帰、ロジスティック回帰、Ridge|
|決定木系|ルールベースでの分岐学習|決定木、ランダムフォレスト、XGBoost|
|SVM系|マージン最大化の境界学習|SVM、SVR|
|ベイズ系|確率モデルに基づいた推論|Naive Bayes、ベイズネット|
|ニューラルネット系|多層・非線形表現の学習|MLP、CNN、RNN、Transformer（深層学習）|
|その他の非パラメトリック系|シンプルな距離ベースなど|k-NN・LDA|


#### 応用領域（分析対象）による分類
|      カテゴリ      |                     概要                 |              代表例             |
|     ----           |                     ----                 |              ----               |
|自然言語処理|人間の言語をコンピュータで理解・生成する技術。テキストの分類、要約、感情分析などを行う。|RNN、Transformer、Naive Bayes|
|音声処理|音声データの解析と生成を行う技術。音声認識（音声→テキスト）や音声合成（テキスト→音声）などを行う。|RNN、WaveNet、Transformer|
|画像処理|デジタル画像の解析・加工技術。画像の特徴抽出（分類）や物体認識、フィルタリングなどを行う。|CNN、Vision Transformer|
|時系列処理|時間に沿ったデータの解析技術。トレンドや季節性を見つけ、未来の予測を行う。|ARIMA、LSTM、Prophet|
|グラフデータ処理|ノードとエッジからなるグラフデータの解析技術。|GCN、GraphSAGE（ニューラルネット系）|


#### 分析アプローチの目的別の分類
|      カテゴリ      |                     概要                 |              代表例             |
|     ----           |                     ----                 |              ----               |
| 探索的データ分析（EDA）|データの構造や傾向を把握するための初期分析。仮説なしでも実施可能。|ヒストグラム、散布図、相関分析|
| 記述分析|現状を正確に把握・報告する。業務報告やKPIモニタリングに有用。|集計表、レポート、BIダッシュボード|
| 仮説検証分析|特定の仮説の正しさを検証する。要件定義や施策評価と相性が良い。|回帰分析、ABテスト、因果推論|
| 予測分析|将来の数値や行動を予測する。モデル精度・運用体制が重要。|機械学習モデル、時系列予測、深層学習|
| 最適化・改善分析|結果をもとに行動を最適化・自動化。PDCAや業務オペレーションと密接。|グロースハック、施策最適化、強化学習|

:::details プロジェクトタイプ（詳細）
※関連記事・書籍：
・20250516_idea_ds.md
　駆け出しデータサイエンティストの未来戦略：得意分野をどう決める？キャリア設計入門
・AI・データ分析プロジェクトのすべて
![](/images/util/dummy_white.png =150x)

1. データ分析プロジェクト
まずは、**自社にとって重要な数値や指標が何であるかを把握する**ために、仮説検証や効果検証を行う「データ分析プロジェクト」を実施します。目的は、売上向上やコスト削減など、業務改善に直結する知見の獲得です。ビジネスを効率化するための代表的なアプローチとして、「改善点の分析→仮説立案と原因分析→効果検証」の分析プロセスが挙げられます。
成果物：分析レポートなど。
![](/images/20250516_idea_ds/flow1.png =350x)

2. データ可視化・BI構築プロジェクト
次に、**得られた数値や指標を継続的にモニタリングできる環境を整える**ために、BIツールを用いてダッシュボードを構築します。これは、データに基づく意思決定を日々の業務に組み込むための基盤づくりです。「**いつ・どこで・誰に**」データのレポートを引き渡すのかを、まず確認します。BIツールには主に、**大規模データへのアクセスと操作・データ加工・集計と可視化・レポーティング**の機能を持ちます。
成果物：BIツールによる可視化ダッシュボードなど。
<br>
3. 機械学習システム構築プロジェクト
さらに、**意思決定プロセスを自動化・最適化する段階に進む**と、機械学習を用いたシステム構築が必要になります。例えば、予測モデルをシステムに組み込み、API経由で定常的に出力を利用する仕組みなどがこれに該当します。
成果物：予測用API、モデル内蔵システム、バッチ処理システムなど。
![](/images/util/dummy_white.png =150x)

※従来の開発とAIシステム開発の違い
|      比較軸        |                 従来の開発     |            AIシステム開発    |
|     ----           |                     ----       |              ----            |
|処理の結果          |常に同じ結果                    | 都度異なる結果               |
|根拠の説明性        |可能                            | 難しい                       |
|開発手法            |主にウォーターフォール          | 主にアジャイル               |
|契約体系            |請負                            | 準委任                       |
|データが与える影響  |正常なデータなら問題なし        | 正常なデータでも精度に影響を及ぼす |
|データ整備の必要性  |不備・整合性の確認              | 前処理も必要                 |
|スケジュールの延期  |原則不可                        | 都度見直しが発生（締め切り時点での<br>完成度の向上を目指す）     |
|予算                |事前に決められた額が前提        | 都度見直しが発生             |
|成果物の権利        |基本的に発注者のもの            | 発注側と開発側で検討が必要   |

<br>
※失敗例
- モデルが完成しても精度が徐々に下がることを見落とす
→制度低下を見越した費用対効果を考慮しておく
- 高すぎる制度を目指す
→最初の段階で高い精度を目指さない。そもそも精度100％はあり得ない。
- 精度向上やスケジュールを守るために開発者の人数を増やす
→増員による改善は期待できない。データを見直した方が効果的。
- 期待値コントロールの失敗
→高すぎる期待に対する認識を改めさせる
<br>
※提案書作成と必須項目
- プロジェクトの全体像
- 位置づけとゴール
- 対象とする課題
- 課題に対するアプローチ
- スケジュール

:::details 最近のAIエージェント技術の進化：キーワードで読み解く
## 🧠 最近のAIエージェント技術の進化：キーワードで読み解く
近年、**LLM（大規模言語モデル）を中心としたAIエージェント**の研究と応用が急速に進化しています。以下のキーワードは、これらの技術の中核をなす重要な概念です。

# 1. **ReAct（Reason + Act）**
ReActは、LLMが**思考（Reason）と行動（Act）を交互に行うフレームワーク**です。
たとえば、検索が必要な質問に対して、まず「考える」→「Web検索をする」→「結果を見てまた考える」といった手順をLLMが繰り返すことで、より精度の高い応答を生成します。
> 🔍例：ReActを使うと、エージェントが「この情報は信頼できるか？」と自問しながら追加情報を検索・判断できる。

## 2. **RAG（Retrieval-Augmented Generation）**
RAGは、**外部の知識ベースから情報を検索（Retrieve）し、それをもとに生成（Generate）を行う手法**です。これは、LLMが学習データにない情報にアクセスできるという大きなメリットを持ちます。
> 📚例：社内ドキュメントを検索して回答する社内QAボットに活用されている。

## 3. **LLM-as-Agent**
「LLM-as-Agent」とは、LLMを**単なる文章生成器ではなく、「意思を持って行動するエージェント」として扱う設計思想**です。
これにより、LLMがAPIを叩いたり、外部ツールを操作したり、メモリを保持したりすることが可能になります。
> 🧭ChatGPTに「ToDoリストを管理して、必要に応じてSlackにリマインドして」と頼むような使い方がこれに該当。

## 4. **Reflection（内省）**
Reflectionとは、**エージェントが自分の過去の判断や行動を振り返り、次の行動を最適化する仕組み**です。成功・失敗の記録に基づいて行動を変えることが可能になります。
> 🔁「過去のタスク失敗理由を分析し、次回は異なるアプローチを取る」といった行動に発展。

## 5. **「心の理論」に基づくAIエージェント**
これは、**人間のように「他者の信念や意図を想定する能力（Theory of Mind）」を持たせたAI**のことです。
AIが他のエージェントや人間の視点を考慮し、協調や駆け引きができるようになります。
> 🧠例：人間の「まだ知らない情報」に配慮した説明をAIが行う、といったケース。

## 6. **マルチモーダルエージェント**
マルチモーダルエージェントとは、**テキスト・画像・音声・動画など、複数の情報モダリティを統合的に処理できるAI**です。
入力が文章だけでなく、図や写真を含む場合でも理解・対話・推論が可能になります。
> 📷例：図を読み取り、質問に答える教育支援AIなど。

## ✨まとめ：これらの要素は連携する
* ReAct や Reflection により「思考→行動→内省」のループが形成され、
* RAG が外部知識の補完を可能にし、
* LLM-as-Agent が柔軟なツール実行や記憶管理を担い、
* 心の理論 や マルチモーダル性 が人間に近い知的対話を可能にする。
これらの技術が組み合わさることで、「一人で考えて、学び、協調するエージェント」が実現に近づいています。
